# Stable inductive fingerprints (soma-hash 2)

Recursive references now record their distance from the current inductive
block, rather than the depth of the whole dependency-hashing traversal.
Previously a memoized block could first be visited inside an unrelated proof
relation. That changed its self-reference encoding, so adding a theorem could
change existing contract and witness fingerprints without changing any of
those checked terms. Constructor return types make this relevant even to
inductives such as equality.

`soma_hash_inductive_order.sh` reproduces the defect before the fix. It checks
all original contracts, witnesses and assumption lists after adding/removing
three recursive proof relations that mention an existing request type and
equality. The original hash suite retains its statement/body/proof/assumption,
constructor/mutual-type, foreign-byte, relocation, universe and cache checks.

This corrects the hash encoding, so its domain version deliberately advances
from `soma-hash 1` to `soma-hash 2`. Stored fingerprints require rechecking;
they must not be compared as if they used the old encoding. The hash format's
pinned example is updated for this explicit version transition. No checked
term, native implementation, extraction layout or trusted assumption changes.
Kykeon's registered generation receipts are regenerated by the compiler and
their runtime products compared separately from fingerprint manifests.
